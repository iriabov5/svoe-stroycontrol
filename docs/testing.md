# Проверки

## Backend

Из папки `backend`, с работающим Docker для Testcontainers:

```sh
./gradlew check javadoc bootJar --no-daemon
```

JUnit Jupiter из BOM Spring Boot проверяет правила ввода и карточек на модульном уровне. Фактические версии зафиксированы в [описании стека](versions.md). Интеграционные тесты поднимают отдельный PostgreSQL 18.7 через Testcontainers, применяют Flyway и обращаются к настоящему HTTP-серверу Spring Boot. Основная база Compose в этих тестах не используется.

Для этапов дополнительно проверяются границы календарных дат, часовой пояс, переходы и их повторы, перестановка, версии, гонки редактирования и создания.

Проверяются нормализация и уникальность email, Argon2id, сессия и смена её ID, ротация CSRF, выход с отзывом прежней cookie, роли и изоляция карточек, безопасный повтор назначения, конкурентные регистрации и назначения, ограничения БД, сортировка и ошибки формата JSON.

## Frontend

Из папки `frontend`, с Node.js 26.13.1:

```sh
npm ci --include=optional
npm test
npm run lint:api
npm run build
npm run format:check
```

Vitest и Testing Library проверяют формы, выбор роли, сохранение несекретных полей при ошибке, пустой список, повтор загрузки и поведение CSRF-клиента. `build` генерирует типы из OpenAPI, проверяет TypeScript и собирает Vite. Генерируемый `src/api/schema.d.ts` исключён из ручного форматирования. Контейнерная сборка выполняет компонентные тесты на закреплённом Node.js перед сборкой frontend.

## Браузерные и контрактные проверки

Сначала запустите Compose по [инструкции](development.md), затем из `frontend`:

```sh
npx playwright install chromium
npm run test:e2e
```

Для другого стенда:

```sh
COMPOSE_PROJECT_NAME=stroycontrol-acceptance BASE_URL=http://localhost:18088 npm run test:e2e
```

Playwright использует реальные frontend, backend и PostgreSQL. Каждый тест создаёт собственные аккаунты с уникальными email. Критический сценарий — регистрация заказчика, создание дома, ошибка и успешное назначение подрядчика, просмотр подрядчиком, обновление страницы и отказ постороннему. Проверяются пустой список, переход с клавиатуры между полями и возврат к входу после отзыва сессии.

Два размера экрана: 1440×1000 и 390×844. На входе, регистрации, создании, карточке и пустом списке запускается axe-core с правилами WCAG 2 A/AA и 2.1 AA; дополнительно проверяется отсутствие горизонтального переполнения. Ответы API сверяются с JSON Schema из `api/openapi.yaml` через Ajv 2020.

HTML-отчёт — `frontend/playwright-report/index.html`; trace и снимки при падении — в `frontend/test-results/`. Сценарии карточек и этапов обновляют пользовательские PNG в `docs/screenshots/`.

## Подготовка стройки: заявка, смета и договор

Новый сквозной сценарий: заказчик заполняет заявку и выбирает финансирование → получает демо-одобрение → отправляет заявку → подрядчик готовит предложение → заказчик согласует смету → подрядчик составляет договор → возврат с замечанием → новая версия договора → согласование → начало и завершение этапа. Проверяются обе ширины экрана и JSON Schema новых ответов.

Backend дополнительно проверяет возврат сметы, скрытые черновики, защиту прямого изменения плана, запрет старта без договора, конкурирующие решения, повторное согласование, откат всего согласования при ошибке создания этапов, альтернативы демо-банка и владельческий доступ к кредитным сведениям. Flyway проверяется отдельно на переходе от V2 с уже начатым этапом. Модульные тесты отклоняют опасные схемы URL, недопустимые даты и денежные значения.

Прежние браузерные сценарии используют явно помеченные LEGACY-фикстуры: после создания собственного тестового объекта helper через Docker Compose/psql задаёт ему прежний режим. Это только подготовка изолированных тестовых данных, не пользовательский API. Поэтому эти проверки требуют доступа к локальному Docker Compose; новый сквозной сценарий работает через публичные UI/API без изменения БД.

Новые PNG: `request-*`, `proposal-*`, `contract-*` в `docs/screenshots/`. Они сняты с работающего frontend/backend на синтетических данных. При повторе тесты перезаписывают снимки.

Картинка планировки в новом браузерном сценарии — собственная SVG-фикстура `e2e/fixtures/house-plan.svg`. Playwright отдаёт её по демонстрационному HTTPS URL через route; это синтетический источник иллюстрации, не действующий внешний сервис. Также проверяются Escape, повторное открытие банковского диалога с клавиатуры и возврат фокуса.
