# Контрольные точки: демонстрация заказчика и подрядчика

Контрольные точки помогают найти следующее действие в существующей карточке дома: начать работу, опубликовать подтверждение, передать этап на приёмку, исправить замечания или завершить строительство. Они не заменяют технический надзор и не подтверждают качество по фотографии.

## Подготовка

Из корня репозитория:

```sh
docker compose up -d --build --wait
npm --prefix frontend ci
./scripts/seed-construction-guide.sh
```

Команда использует установленный браузер Playwright. Если Chromium ещё отсутствует, установите его из frontend командой `npx playwright install chromium`. Откройте http://localhost:8088. Команда выводит три синтетических email и пароль `example-password-123`. Точные названия, ID, email и состояние набора сохраняются в `output/construction-guide-demo.json`; файл локальный и не включается в Git. Реквизиты меняются при каждом запуске, повторный запуск создаёт отдельный набор. При сбое файл сохраняет последний шаг и собственные созданные ID; чужие данные не меняются и не удаляются.

Все объекты имеют название «Демо · … · guide-…». Первый объект — «Дом семьи Орловых», второй — «Каркасный дом на Озёрной». Есть отдельная новая карточка без плана. Имена содержат уникальный маркер набора.

Новые проекты проходят обычные регистрацию, организацию, назначение, заявку, согласование сметы и договора. Они не переводятся в LEGACY прямым SQL. Синтетические иллюстрации загружаются штатным файловым API в закрытый SeaweedFS и связываются с журналом. Дополнительные характеристики паспорта заполняет одноразовая backend-команда только с профилем `construction-demo`, проверяя владельца и маркер новых объектов. Обычный backend не публикует для неё mutation endpoint.

## Заказчик

Войдите email заказчика из вывода команды. На стартовом экране найдите индикатор объектов с требуемым действием. Перейдите по нему: откроется приёмка первого фундамента «Дома семьи Орловых».

Вернитесь в карточку дома. В компактном обзоре видны паспорт и подрядчик; блок «Контрольные точки» показывает собственное действие заказчика. Второй фундамент остаётся отдельной точкой в «Все контрольные точки».

Откройте проверку сдачи, изучите синтетическое фото и выберите «Вернуть с замечаниями». Введите «Демонстрация: уточните подпись подтверждения» и отправьте. Сдача показывает «Нужны исправления», собственный индикатор заказчика обновляется без повторного входа.

## Подрядчик

Войдите email подрядчика того же набора. В первом доме главная точка ведёт к исправлению замечаний. После исправления используйте «Сдать повторно», заполните итог, выберите запись с загруженным фото и отправьте на приёмку. Требование действия переходит заказчику.

Во втором доме найдите точку инженерных сетей. Перейдите к добавлению подтверждений, заполните «Что сделано», добавьте фото через «Добавить фото или PDF» и подпишите его как синтетический пример. Нажмите «Опубликовать». После возврата в карточку раскройте «Все контрольные точки»: точка сообщает «Подтверждения добавлены», а требование публикации снимается с шапки и списка этапов. PDF, внешний URL и загруженный без публикации файл этого действия не снимают. Публикация не означает приёмку этапа.

## Приёмка и завершение

Под заказчиком примите повторную сдачу первого фундамента. Он больше не требует повторной проверки. Подрядчик проходит второй фундамент: начинает работы, публикует подтверждение, отмечает работы завершёнными, затем передаёт на приёмку. До передачи точка просит именно сдачу подрядчика.

После принятия всех этапов дома точка «Перед передачей дома» ведёт к сводке завершения. Нажмите «Подтвердить завершение строительства», затем «Подтверждаю завершение». Дата и итог сохраняются, строительных действий больше нет; история остаётся доступна. Банковская проверка в ипотечном проекте остаётся отдельным процессом.

## Ограниченные права и ошибки

Email сотрудника с правами на документы открывает второй дом без собственных команд выполнения работ. Его шапка не считает действия подрядчика собственными задачами. Посторонний аккаунт и прямой URL чужой карточки получают 404.

У новой карточки без плана видны объяснение подготовки и отсутствие этапов нужного вида. Не требуется обходить согласование или добавлять фиктивные этапы.

При сетевом сбое блок сообщает о неудачном обновлении и предлагает повтор. Ошибка не показывается как нулевое число действий. Браузерный тест воспроизводит этот снимок управляемым ответом 500; серверный тест отдельно проверяет Problem для противоречивых источников.
