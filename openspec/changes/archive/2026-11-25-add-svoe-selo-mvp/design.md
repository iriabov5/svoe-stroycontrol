# Решения

- Отдельная точка входа `mvp/` в существующем репозитории. Старое приложение остаётся работоспособным; новый фронтенд не обращается к его API.
- Единое локальное состояние: смета, настройки и обязательства календаря, история кадастра, полисы, заявки. Владелец данных — гость либо профиль по телефону.
- `guest_data`, `user_data_{phone}`, отдельный ключ текущего профиля. При входе гостевые изменения объединяются с профилем без потери истории и документов; гостевая копия удаляется только после успешной записи. Выход отделяет данные профиля от нового гостевого сеанса.
- Очередь одного действия после входа: экспорт, заявка, сохранение, загрузка, уведомления либо покупка полиса. Закрытие окна отменяет действие.
- Файлы PDF/JPG/PNG сохраняются как data URL; ограничение размера и обработка переполнения localStorage показываются пользователю. Не заявлять об отправке настоящему банку.
- Даты обязательств — календарные даты без UTC-сдвига. При добавлении месяцев день ограничивается последним днём целевого месяца. Статусы просрочки вычисляются относительно текущей даты; документы и принятие имеют приоритет.
- Страхование создаёт локальный демополис и закрывает выбранное либо ближайшее непринятое обязательство страхования; покупка недостроя не закрывает ипотечную страховку.
- UI: брендовые цвета из ТЗ, Manrope, крупная фотография дома на главной, лаконичные карточки, доступные диалоги, мобильная навигация. Ресурсы поставляются вместе с приложением.
- Обычный ввод, расчёты, даты и история сохраняются автоматически; явные профильные действия и экспорт требуют демовхода.
