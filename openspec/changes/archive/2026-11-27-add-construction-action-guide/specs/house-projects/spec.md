## ADDED Requirements

### Requirement: Участники видят паспорт дома с происхождением значений

Система SHALL показывать заказчику и участникам назначенной команды read-only паспорт внутри существующей карточки: площадь, этажность, материал стен, тип фундамента, кровлю и срок. Источники SHALL различаться: площадь и этажность — текущая доступная строительная заявка, технические характеристики — отдельно заполненные общие сведения дома, плановый срок — максимальная плановая дата завершения исполняемого согласованного плана. Для LEGACY срок берётся из его действующего плана. До появления такого плана желаемая дата окончания из заявки SHALL отображаться только как «Желаемое завершение», а не согласованный срок.

Значения SHALL NOT восстанавливаться по названию проекта, свободному тексту пожеланий, умножению габаритов вместо сохранённой площади или по фотографии. Отсутствующие значения SHALL передаваться как null и отображаться как «Не указано»; при отсутствии всех значений показывается компактное пояснение без пустой большой панели. Наличие части полей SHALL NOT скрывать остальные заполненные поля. При завершении дома паспорт сохраняет чтение и подпись об источниках, не становится подтверждением фактических характеристик.

Площадь и этажность SHALL NOT дублироваться во второй изменяемой записи паспорта. В первой итерации пользовательского редактора дополнительных технических характеристик нет; они могут отсутствовать у обычных проектов. Демонстрационный набор заполняется контролируемой командой разработки. Будущее редактирование требует отдельного контракта и не меняет отправленную заявку задним числом.

#### Scenario: Все сведения доступны
- **WHEN** участник открывает проект с заявкой, заполненными техническими сведениями и согласованным планом
- **THEN** он видит все шесть характеристик, дату планового завершения из плана и пояснение источников

#### Scenario: Старый объект без паспорта
- **WHEN** участник открывает LEGACY-проект без заявки и технических характеристик
- **THEN** карточка открывается без ошибки, фиктивные параметры не появляются; имеющаяся дата плана доступна независимо от остальных полей

#### Scenario: Частично заполненная заявка
- **WHEN** площадь и этажность заданы, а фундамент и кровля неизвестны
- **THEN** известные значения видны, неизвестные обозначены текстом; никаких демонстрационных значений для обычного проекта нет

#### Scenario: Изменение источника
- **WHEN** заказчик сохранил допустимое изменение площади черновика либо изменился разрешённый план LEGACY
- **THEN** следующее чтение паспорта показывает соответствующее сохранённое значение, а второй независимой копии для синхронизации не существует

#### Scenario: Желаемый срок до согласования плана
- **WHEN** у заявки есть желаемая дата завершения, но исполняемого плана нет
- **THEN** видна подпись «Желаемое завершение» и источник «Пожелания заказчика»

#### Scenario: Неполный план не даёт обещанного срока
- **WHEN** план существует, но хотя бы у одного этапа отсутствует плановая дата окончания
- **THEN** паспорт не выдаёт максимум остальных дат за срок всего дома; плановый срок равен null, пожелание при наличии остаётся отдельно обозначенным

#### Scenario: Чужой пользователь и закрытые данные
- **WHEN** посторонний аккаунт обращается к паспорту по прямому API URL
- **THEN** получает 404 PROJECT_NOT_FOUND; ответ для разрешённого подрядчика не содержит бюджета, кадастровой проверки и ипотечного расчёта

#### Scenario: Обновление существующей базы
- **WHEN** приложение обновляется на базе с уже применённой миграцией V12 участка и ипотеки
- **THEN** новые структуры паспорта добавляются без конфликта версий и изменения прежних строк, заявки, расчёты, файлы и доступ к ним сохраняются
