# Контрольные точки строительства

## ADDED Requirements

### Requirement: Участник видит контрольные точки проекта

Сервис ДОЛЖЕН показывать заказчику и участнику назначенной подрядной организации
read-only список контрольных точек на доступной им карточке проекта.

#### Scenario: Заказчик видит действие до заливки фундамента

- **WHEN** этап фундамента ожидает подтверждений подрядчика
- **THEN** заказчик видит ответственного, объяснение и переход к этапу или журналу

#### Scenario: Посторонний пользователь не получает точки проекта

- **WHEN** аккаунт не имеет доступа к карточке
- **THEN** сервис возвращает тот же результат отсутствия ресурса, что и для карточки

### Requirement: Карточка не подменяет строительный контроль

Сервис ДОЛЖЕН представлять контрольную точку как напоминание о подтверждениях и
следующем действии, а не как заключение о соответствии работ нормам или проекту.

#### Scenario: Карточка готовности отображается подрядчику

- **WHEN** у подрядчика есть доступ к работам проекта
- **THEN** он видит требуемое действие без кредитных сведений заказчика

### Requirement: Участник видит безопасный контекст демо-объекта

Сервис ДОЛЖЕН показывать участнику проекта общие параметры дома, если они заполнены,
и ДОЛЖЕН сохранять доступность карточки, если у объекта параметры отсутствуют.

#### Scenario: Демо-проект показывает паспорт дома

- **WHEN** заказчик или назначенный подрядчик открывает демо-проект с заполненным паспортом
- **THEN** он видит площадь, этажность, конструкцию, фундамент, кровлю и плановый срок
- **AND THEN** паспорт не показывает банковские или персональные данные

#### Scenario: Обычный проект создан до паспорта

- **WHEN** участник открывает существующий проект без параметров дома
- **THEN** карточка открывается без ошибки и не показывает фиктивные значения

### Requirement: Действие выделено без отдельного центра уведомлений

Сервис ДОЛЖЕН выделять этап и контрольную точку, где текущей роли требуется действие,
и предоставлять доступную ссылку из шапки кабинета на первый такой объект.

#### Scenario: У заказчика есть действие по фундаменту

- **WHEN** контрольная точка фундамента ожидает заказчика
- **THEN** в шапке отображается текстовое число требующих действия объектов
- **AND THEN** ссылка ведёт к первому доступному проекту

#### Scenario: У подрядчика есть действие по инженерным сетям

- **WHEN** контрольная точка инженерных сетей ожидает подрядчика
- **THEN** этап и контрольная точка объясняют требуемый шаг текстом
- **AND THEN** индикатор не отображается, если действий для роли нет

#### Scenario: Подрядчик приложил подтверждение к этапу

- **WHEN** в журнале этапа в работе опубликована запись с фотографией
- **THEN** действие «Добавить подтверждения в журнал» больше не отображается в шапке и списке этапов
